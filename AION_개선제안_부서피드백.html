부서 설명회 피드백을 반영한
AION 사업계획 작성 체계 개선안

설명회에서 안내한 현재 작성 절차를 기준으로, 부서 담당자들이 제기한 작성 부담을 줄이면서도 원인행위·실행·결과보고의 뼈대는 남기는 수정안입니다.

대상: 기획처 · 부서 사업담당자 기준 자료: AION 설명회 발표자료 작성일: 2026. 8. 28. 상태: 검토·의견 수렴용
이 문서의 목적. 새 매뉴얼을 확정하기 전에, 바꿀 점 두 가지를 먼저 합의하기 위한 제안서입니다. ① PDCA를 활동 행마다 촘촘히 쓰지 않게 단순화 ② 사업분류(C1~C5)를 맨 앞이 아니라 작성 후 AI 초안 → 담당자 수정으로 이동.

0한 장 요약

제안 1. PDCA 작성 부담 완화

  • P — 원인행위만 작성
  • D — 해당 사업의 실행 계획을 꼼꼼히 작성
  • C — 결과보고서만, 종료 후 2주 이내
  • 예산은 행마다가 아니라 P / D / C 각 한 칸

제안 2. 분류표를 맨 뒤로

  • 지금은 위자드 가장 먼저 C1~C5를 고르지 않으면 진행 불가
  • 앞으로는 내용을 쓴 뒤, AI가 초안 분류를 제안
  • 담당자는 틀린 칸만 수정

1제안 배경

설명회 발표자료는 사업계획을 로그인 → 위자드(분류가 1단계) → Step 1~5로 안내합니다. Step 2 추진계획은 PDCA를 활동 행으로 쪼개고, 행마다 일정·내용·원인행위·금액(천원)을 채우도록 되어 있습니다.

부서 설명 이후 담당자 쪽 공통 의견은 다음 두 가지로 모입니다.

  1. PDCA를 행 단위로 매우 촘촘히 쓰는 수고가 크다. 실제 업무는 원인행위 → 사업 실행 → 결과보고인데, 화면은 활동 행을 계속 늘리며 금액까지 나눠 넣게 한다.
  2. 맨 처음 분류표(C1~C5)를 고르는 것이 어렵다. 아직 사업 내용이 없는데 분류부터 확정해야 하고, 고르기 전에는 다음 단계로 가지 못한다.
이 제안은 설명회에서 강조한 원칙 — 부모–자녀 연결, 금액 단위 천원, 제출 후 내부공문(기획처) — 은 유지한 채, 담당자가 직접 타이핑하는 밀도만 낮추는 방향입니다.

2현재 체계 (설명회에서 안내한 방식)

2-1. 위자드 순서 — 분류가 1번

① 사업분류 C1~C5 → ② 부모사업 → ③ 사업명 → ④ 조건 → ⑤ 예산 → ⑥ 목적 → ⑦ AI 생성 → ⑧ 편집 전환

발표자료 표현: 「좌측에서 사업 분류를 선택해 주세요. 분류를 고르기 전에는 다음 단계로 진행되지 않습니다.」

2-2. PDCA — 활동 행마다 일정·원인행위·금액

지금 쓰는 규칙

  • P 계획 · D 실행 · C 점검 · A 환류를 행을 늘려 세분
  • 행마다 일정, 내용, 원인행위 여부, 금액
  • 금액은 P·D 행에만, 행 합계 = 총예산
  • C·A는 비예산

담당자가 느낀 점

  • 한 사업을 10행 이상으로 쪼개야 할 것 같다
  • 행을 추가할 때마다 예산을 나눠 넣는 일이 반복된다
  • 원인행위·실행·결과보고가 한 흐름인데 화면은 너무 잘게 쪼갠다

3제안 1 — PDCA를 실무 3덩어리로 단순화

활동 행을 무한히 늘리는 대신, P / D / C 각 구역의 역할을 고정합니다. (설명회의 A 환류는 C 결과보고에 흡수하는 방향으로 검토합니다.)

3-1. P — 원인행위만 작성

계획 단계에 요구조사·설계·입찰을 여러 행으로 쓰지 않습니다. 이 사업을 집행하기 위한 원인행위(기안·위원회)만 적습니다.

원인행위 경로 판단 (사업 총액 기준, 원 단위)
  • 500만 원 이상 → 위원회
  • 500만 원 미만
    • 학생 행사 등 주요 안건 → 위원회
    • 그 외 → 부서 내부기안 필수
AION 화면 금액 단위는 천원입니다. 500만 원은 5,000천원에 해당합니다. 위원회 종류(행정위원회 / 혁신운영위원회 등)는 기존 규정·기획처 안내에 따릅니다. 지출원인행위 구분은 설명회와 같이, 담당자 선택을 참고하되 규정에 따라 기획처에서 조정될 수 있습니다.

3-2. D — 해당 사업의 사업계획을 꼼꼼히 작성

실행 단계가 본문입니다. “무엇을 할지”를 한 덩어리로 쓰되, 아래 항목이 빠지지 않게 합니다.

D에 넣을 실행 항목 (체크리스트)

  • 사업 홍보 — 대상, 채널, 시기
  • 운영 — 일정, 장소, 인력, 진행 방식
  • 결과보고회 — 개최 여부·시기
  • 세금 납부 — 해당 시 원천세 등 처리
  • 인건비 지급 — 해당 시 지급 대상·시기
  • 청구 — SU-WINGS·그룹웨어 지출 청구 시점

세부 일정은 행을 쪼개지 않고 D 본문 안에서 시기별로 적어도 됩니다. 핵심은 실행에 필요한 일이 한눈에 보이는 것입니다.

3-3. C — 결과보고서 작성만

  • 점검 단계에 만족도·KPI·검수를 여러 행으로 미리 쪼개 쓰지 않습니다.
  • 결과보고서 작성이 C의 할 일입니다.
  • 기한: 사업 종료 후 2주 이내

3-4. 예산 — 행마다가 아니라 P / D / C 각 한 번

구분 현재 (설명회) 제안
입력 단위 활동 행을 추가할 때마다 금액 입력 P 한 칸, D 한 칸, C 한 칸만 배정
합계 규칙 P 행 합 + D 행 합 = 총예산
C·A는 비예산		 P 배정 + D 배정 + C 배정 = 총예산
(C에도 필요하면 배정 가능)
Step 4와의 관계 P 계획 / D 계획을 계정과목 표로 쪼갬 P·D·C 각 배정액을 계정과목으로 쪼개는 방향으로 후속 설계
기대 효과. “행을 하나 늘릴 때마다 예산을 다시 나누는” 일이 사라집니다. 담당자는 원인행위(P) · 실행(D) · 결과보고(C)에 얼마를 둘지만 맞추면 됩니다.

3-5. 전후 비교 (작성 모습)

단계 현재 — 행을 계속 추가 제안 — 구역당 역할 고정
P 계획 사업계획, 요구조사, 원인행위 기안, 설계, 입찰을 각각 행으로 작성. 행마다 금액 0 또는 소액. 원인행위만. 500만 원 기준·주요 안건 여부로 위원회 / 부서 내부기안을 결정. 예산은 P에 한 번.
D 실행 홍보, 구축, 교육, 시범 운영 등을 행으로 쪼개고 행마다 금액. 사업계획 본문. 홍보·운영·결과보고회·세금·인건비·청구를 한 계획으로 작성. 예산은 D에 한 번.
C 점검 피드백, 만족도·KPI, 준공검수를 행으로 나열. 금액은 비예산. 결과보고서만. 종료 후 2주 이내. 필요 시 C에 예산 한 번.
A 환류 개선, 성과공유, 차년도 계획을 별도 행. 비예산. 별도 작성 부담을 두지 않고, C 결과보고에 환류·차년도 시사점을 포함.

4제안 2 — 사업분류는 맨 마지막에, AI 초안을 고치는 방식

설명회 위자드는 분류(C1~C5)를 고른 뒤에야 부모사업·사업명으로 넘어갑니다. 담당자는 “이 사업이 대상·환경·시점·목적·방법 중 어디에 해당하는지”를 내용도 쓰기 전에 확정해야 합니다.

현재

분류 → 내용 작성 → AI 초안. 분류가 입구를 막는다.

제안

내용 작성 → AI가 작성문을 분석해 분류 초안 → 담당자가 수정·확정.

4-1. 바꿀 작성 순서

현재

분류 C1~C5 → 부모사업 → 사업명·조건·예산·목적 → AI 생성 · Step 편집

제안

부모사업 → 사업명·조건·예산·목적 → P·D·C 작성 → AI가 분류 초안 → 담당자 수정·확정

4-2. 담당자가 하는 일

  1. 지금까지 적은 사업명, 목적, P(원인행위), D(실행계획), C(결과보고 계획)를 AI가 읽습니다.
  2. C1 대상, C2 환경·지역, C3 시점·주기, C4 목적, C5 사업 방법을 대략 채워 보여 줍니다.
  3. 담당자는 틀린 항목만 고치고 확정합니다. 처음부터 빈 분류표를 채울 필요는 없습니다.
분류 자체(C1~C5 체계)는 유지합니다. 바꾸는 것은 언제, 누가 초안을 만드느냐입니다. 성과지표·중장기발전계획 연동에 분류가 쓰이므로, 최종 확정은 여전히 담당자 책임입니다.

5기대 효과

항목 달라지는 점
작성 시간 PDCA 행을 10개 이상 쪼개지 않아도 됩니다. 원인행위·실행·결과보고 세 구역만 채우면 됩니다.
예산 입력 행 추가마다 금액을 재분배하지 않습니다. P/D/C 세 숫자만 총예산과 맞춥니다.
원인행위 500만 원·주요 안건 기준으로 위원회 / 부서 내부기안이 분명해집니다.
결과 관리 C를 “종료 후 2주 내 결과보고서”로 고정해, 계획 단계의 가상 점검 행을 줄입니다.
분류 정확도 내용이 있는 상태에서 AI 초안을 고치므로, 빈 화면에서 C1~C5를 찍는 부담이 줄어듭니다.

6합의가 필요한 사항

시스템 수정에 들어가기 전에 아래를 정해 두면 이후 화면 설계가 흔들리지 않습니다.

  1. 500만 원 기준은 사업 총액인지, 원인행위 건별 금액인지.
  2. 주요 안건의 범위 — 학생 행사 외에 대외 행사, 공사, 용역을 포함하는지.
  3. C 예산 — 결과보고서 관련 비용만 두는지, 기본은 0천원인지.
  4. A(환류)를 C에 흡수해도 중장기 성과관리 보고에 빈칸이 없는지.
  5. Step 4 계정과목을 P/D/C 세 배정액에 맞춰 표를 세 개로 둘지, 지금처럼 Plan/Do 두 표로 둘지.
  6. 분류 AI 초안이 틀렸을 때, 제출 전 담당자 확정 없이 넘어가지 못하게 막을지.
이 문서는 확정안이 아닙니다. 부서 의견을 더 받은 뒤, 설명회 자료·작성 가이드의 해당 장표(위자드 분류, Step 2 PDCA)를 함께 고치는 것을 다음 단계로 둡니다.

7다음 단계 (안)

  1. 이 제안서에 대한 부서·기획처 의견 수렴
  2. 합의된 규칙을 화면 문구로 풀어 개발에 전달 (P 원인행위 분기, D 체크리스트, C 2주 기한, PDC 예산 3칸, 분류 후순위)
  3. 반영 후 설명회 발표자료·사업계획 가이드의 해당 페이지를 수정
기준 자료: AION 통합 성과관리 체계 설명회 발표자료 (suai.cloud 사업계획 작성 흐름, 위자드 ①분류, Step 2 PDCA).
